Connect / Disconnect as a status chip — prototype

Today the control is a plain button in the project panel whose label swaps between Connect all and Disconnect all, driven by one boolean. The host already tracks more: BusConnState is Connecting / Connected / Error { reason } per logical bus. The chip shows the aggregate the model already knows.

Both themes use the app’s own tokens.

The five states — one width, one shape

Every state occupies the same footprint, so the chip never resizes as a connection progresses and a toolbar never reflows under the pointer. The count is tabular-numeric and right-aligned for the same reason: the digits change, the layout does not.

Sibling check against the real colour chip

The swatches below are rendered from index.css’s own .color-chip rules — 2px radius, a 1px --border-wash hairline. The status chip takes the same radius and the same edge weight, and its indicator is a rounded square rather than a circle, so the family reads as one. What it adds is tinting that edge to carry state; an idle chip is the plain hairline, identical to a colour chip’s.

The state vocabulary this proposes

StateWhenPressing does
Not connectedNothing subscribedConnect
ConnectingAny subscribe in flight — BusConnState::ConnectingNothing, or cancel — undecided
ConnectedEvery bound bus ConnectedDisconnect
DegradedAt least one Connected, at least one ErrorDisconnect
FailedEvery attempt ErrorRetry

Degraded is the state today’s button cannot express, and it is not exotic: one adapter unplugged among three leaves the app connected and quietly missing a third of the traffic. Whether Failed should be distinct from Not connected is a genuine open question — both mean “no frames are flowing”, but only one means something went wrong.
