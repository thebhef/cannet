Events point at signals — prototype

Task 107. An event gains a list of subjects — signals, messages, or other events. An event→event link is untyped — just a link; the events’ colors and labels establish what a pair means. All highlighting is transient — it holds while an event row is hovered or selected and leaves nothing behind — and a linked pair’s extent band appears only while one of its two events is selected or hovered; at rest the plot shows just the marker lines. (Fidelity caveat: the trace view and plot panel here show the general shape only, not their real behaviour — the app’s existing interactions, cursor/note placement included, are not modelled. This prototype proposes no change to any existing surface; the proposals are exactly the subject chips, the extent bands, the transient highlight, and the authoring/linking gestures. Approved with that reading, owner ruling 2026-08-21.)

The plot, and creating an event from signals

Select signals in the legend, then Shift+click in the plot: a new event lands at the clicked time with those signals as its subjects. Hover or select any event (flag here, or row below) and its subject series stay lit while the rest dim; a span brightens its band.

The events view: subjects on the row, and linking

The rows are the app’s own event rows; the subject chips are the one new element — signal (colored swatch), message (arbitration id), event (↔ the linked event’s label). At most two chips show inline; more overflow into a … expansion (the status-bar prototype’s pattern — the overtemp row exercises it). A signal or message reference is structural — message ID plus signal field — so it never breaks: unresolved right now, it renders muted (the contactor row’s TorqueReq). Only event references die, with their event. Click selects; Mod+click multi-selects; with exactly two selected, Link events activates, and selecting either end of a linked pair shades the plot between them.

Settled by owner rulings 2026-08-21

  • Chip density: overflow into a … expansion, the status-bar prototype’s pattern (shown above).
  • Reference form: structural — a message reference is the arbitration ID, a signal reference is message ID + signal field name. No database identity is stored; the reference resolves against whatever databases are assigned at render time, and remains (rendered muted) when unresolvable.
  • Broken references: only an event reference dies (with its deleted event) — no broken-chip state anywhere.
  • Band styling: event-colored wash at low opacity, shown only while a linked event is selected or hovered.
  • Linking gesture: multi-select + toolbar button.
