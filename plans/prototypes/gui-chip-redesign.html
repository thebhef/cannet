The chip language — GUI polish prototype

Task 108. One control silhouette everywhere — the .color-chip shape (2px radius, --border-wash hairline) already carried by the connection-chip and status-bar prototypes — with smaller controls, a common icon set, and state expressed on the hairline. This page restyles the chrome only: every control keeps its exact command, order, and behaviour; nothing here proposes changing what the toolbar does, and the icons are hand-drawn placeholders for whatever set is adopted.

Both themes use the app’s own tokens.

      Per surface: the toolbar keeps every command in today’s order (Import shows the busy hairline-pulse per click; the seven “Add X” buttons collapse into the Add ▾ menu — shown as the proposal, still an open question). The trace toolbar turns run controls and the mode toggle into segmented chips and the checkboxes into pressed toggles. The plot toolbar carries its complete control set: the shared run controls plus the plot-only “all data”, add area, fit x / y, the solo cluster (field + paging + clear as one unbreakable unit, moved left so it spills into the … menu only when it really must), follow, points, the cursor-mode segment (x / y / note as icon buttons — press the active one again for off), clear cursors, and the perf chip — icon-only where the icon is unambiguous, a word where it is not. Two things the app does differently, deliberately: the perf read-out is a <span> rather than a button (a read-out is not pressable, and it carries no dot), and the run controls and “All Data” are still the shared TraceControls buttons — they become chips in the trace-panel sweep, which owns that component. The catalog-reload button is retired (owner ruling 2026-08-21 — it has outlived its usefulness). The measurements strip needs rework and stays hidden (owner ruling 2026-08-21) — no toggle anywhere until it is reworked (MeasurementMenu / the measurements strip in PlotPanel.tsx, backlogged). In the app hidden is the ruling and no toggle only the mechanism, so the strip is suppressed on read as well: it does not draw whatever a saved config says (MEASUREMENT_STRIP_DRAWS), and the stored preference is deliberately left intact for the rework to inherit. Hover anything for its tooltip (the full phrases from the app). Same commands, same order — this is chrome only. Plot 2 below is the same toolbar at full width, unwrapped.

      The icon set — full inventory

      Every icon this page uses, by name and assignment — this is the set (owner ruling 2026-08-21): hand-drawn, 14px grid, 1.4px rounded stroke, no external icon library. Implementation ships these as an in-repo registry (one shared SVG sprite); this sheet is the registry’s reference, and this page is kept after dev as the living design reference. One icon, one meaning, audited 2026-08-21: the bus-health zigzag collided with signals and is redrawn as a bus topology; db split from db-add (panel vs. action). Where one icon serves several commands it is the same verb deliberately — save for every save, plus for every add, search for every filter box, clear for every clear — and the label or tooltip names the object.

      control shape3px radius, --border-subtle, 13px type the .color-chip silhouette: 2px radius, --border-wash hairline, 12px type, 22px tall
